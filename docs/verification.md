# Верификация требований — Finance Tracker API

Данный документ содержит результаты верификации каждого требования из [спецификации требований](requirements.md). Для каждого требования указан способ проверки и результат сверки с работающим приложением.

---

## 1. Функциональные требования

| ID | Требование | Способ проверки | Результат |
|----|-----------|----------------|-----------|
| FR-01 | Регистрация пользователя с email, паролем (≥6 символов) и полным именем | **Тест**: POST `/api/users/register` с валидным телом → HTTP 201 с JWT-токеном. POST с паролем < 6 символов → HTTP 400. POST без fullName → HTTP 400. |  Соответствует |
| FR-02 | Уникальность email при регистрации | **Тест**: Повторный POST `/api/users/register` с тем же email → HTTP 409 Conflict. |  Соответствует |
| FR-03 | Хеширование пароля BCrypt | **Инспекция кода**: `AuthServiceImpl.register()` вызывает `passwordEncoder.encode(password)`. **Тест**: Проверить в БД, что поле `password` начинается с `$2a$`. |  Соответствует |
| FR-04 | Авто-вход при регистрации | **Тест**: POST `/api/users/register` → ответ содержит поле `token` с валидным JWT. |  Соответствует |
| FR-05 | Аутентификация по email/паролю | **Тест**: POST `/api/users/login` с корректными данными → HTTP 200 + JWT. |  Соответствует |
| FR-06 | JWT содержит email, срок 24ч | **Тест**: Декодировать JWT → поле `sub` содержит email, `exp - iat` = 86400 секунд. |  Соответствует |
| FR-07 | Создание счёта с именем и типом | **Тест**: POST `/api/accounts` с `{"name": "Test", "type": "CARD"}` → HTTP 201. |  Соответствует |
| FR-08 | Начальный баланс 0.00 | **Тест**: POST `/api/accounts` → ответ содержит `balance = 0.00`. |  Соответствует |
| FR-09 | Список счетов пользователя | **Тест**: GET `/api/accounts` с JWT → HTTP 200, список содержит только счета текущего пользователя. |  Соответствует |
| FR-10 | Создание пользовательских категорий | **Тест**: POST `/api/categories` с `{"name": "Еда"}` → HTTP 201 с `isSystem = false`. |  Соответствует |
| FR-11 | Уникальность имён категорий | **Тест**: Создать категорию "Еда", затем "еда" → HTTP 409 Conflict. |  Соответствует |
| FR-12 | Отображение категорий | **Тест**: GET `/api/categories` → ответ содержит системные и пользовательские категории. |  Соответствует |
| FR-13 | Транзакции INCOME/EXPENSE | **Тест**: POST `/api/transactions` с `amount = 100, type = INCOME` → HTTP 201. С `amount = -5` → HTTP 400. |  Соответствует |
| FR-14 | Корректировка баланса | **Тест**: Транзакция INCOME увеличивает баланс, EXPENSE — уменьшает. |  Соответствует |
| FR-15 | Атомарная корректировка баланса | **Инспекция кода**: `JpaAccountRepository.adjustBalance()` — единый SQL UPDATE. |  Соответствует |
| FR-16 | Сортировка транзакций | **Тест**: GET `/api/transactions/account/{id}` → упорядочены от новых к старым. |  Соответствует |
| FR-17 | Изоляция данных пользователей | **Тест**: Запрос чужого счёта → HTTP 404. |  Соответствует |
| FR-18 | Ошибки в формате RFC 7807 | **Тест**: Вызвать ошибку (404) → ответ содержит поля `type`, `title`, `status`, `detail`. |  Соответствует |

## 2. Нефункциональные требования

| ID | Требование | Способ проверки | Результат |
|----|-----------|----------------|-----------|
| NFR-01 | Stateless аутентификация | **Инспекция**: `SecurityConfig` устанавливает `SessionCreationPolicy.STATELESS`. |  Соответствует |
| NFR-02 | Время ответа < 500 мс | **Нагрузочное тестирование**: Выполнить 100 параллельных запросов. | Не проверено (нет тестов) |
| NFR-03 | Пароли не в открытом виде | **Инспекция БД**: `SELECT password FROM app_user`. |  Соответствует |
| NFR-04 | Миграции через Flyway | **Инспекция**: Наличие скриптов в `src/main/resources/db/migration/`. |  Соответствует |
| NFR-05 | OpenAPI + Swagger UI | **Тест**: GET `/swagger-ui.html` загружается. |  Соответствует |
| NFR-06 | Maven Wrapper | **Тест**: Наличие `mvnw` скриптов в репозитории. |  Соответствует |
| NFR-07 | Docker Compose | **Тест**: `docker-compose.yml` запускает PostgreSQL на порту 5432. |  Соответствует |

## 3. Обнаруженные дефекты кодовой базы

При верификации требований и инспекции кода обнаружены следующие технические долги и дефекты, которые зарегистрированы в [ISSUES.md](../ISSUES.md):

| № | Описание дефекта | Ссылка на Issue |
|---|------------------|-----------------|
| 1 | В миграции схемы БД создана таблица `budget`, но полностью отсутствует её реализация в Java-коде (мёртвый код/избыточная схема) | ISSUE-001 |
| 2 | Отсутствуют операции обновления и удаления (PUT/DELETE эндпоинты) для основных сущностей (Account, Transaction, Category) | ISSUE-002 |
| 3 | Требование к производительности NFR-02 (время ответа < 500 мс) не верифицировано, так как отсутствуют нагрузочные тесты | ISSUE-003 |
